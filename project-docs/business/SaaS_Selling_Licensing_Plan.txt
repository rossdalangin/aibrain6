PART 3: TECHNICAL ARCHITECTURE OF THE CRYPTOGRAPHIC LICENSING SYSTEM
--------------------------------------------------------------------------------
To protect premium features and prevent users from simply modifying local options
or database settings to unlock free plans, we use cryptographically signed licenses.

A. GENERATION (SaaS Master Server / wp-ai-licensing):
   1. When a user buys a plan on Stripe, a webhook fires to the master site.
   2. The master site generates a unique license key starting with the plan's prefix,
      e.g., `NEXUS-AGENCY-XXXX-XXXX`.
   3. It stores this key in the main registry database and maps it to the user's
      email and active status.

B. ACTIVATION & SIGNING PROCESS (wp-ai-licensing REST Endpoint):
   When a client activates their key:
   1. The client site makes a POST call to:
      `POST https://nexus-ai-saas.com/wp-json/nexus-licensing/v1/validate`
      with parameter `license_key`.
   2. The master server validates the key's status. It selects the associated plan
      (e.g., `agency`).
   3. It calculates a cryptographic signature of the parameters using a secure HMAC
      SHA-256 with a master secret key (salt):
      `$signature = hash_hmac('sha256', $license_key . '|' . $plan, $secret);`
   4. The server returns the payload containing `plan`, `signature`, and `expires_at`.

C. CLIENT VALIDATION & BOUNDARY ENFORCEMENT (wp-ai-workforce):
   1. The local plugin verifies the payload's signature using the shared secret key.
   2. If the signature matches, the plugin stores:
      `nexus_ai_license_key`
      `nexus_ai_active_plan`
      `nexus_ai_license_signature`
   3. If the signature does not match (due to hacking or database tampering), the
      method `BillingController::verify_active_license()` returns false, and the
      system automatically falls back to the `starter` tier, lock-shielding the app.
   4. When the user attempts to deploy a new AI Agent via the `/employees` endpoint:
      - The server checks if `current_agent_count >= plan_limit`.
      - If met, it rejects the request with a `403 Forbidden` response: "Plan limit reached. Please upgrade."

--------------------------------------------------------------------------------
PART 4: STANDARD OPERATING PROCEDURES (SOP)
--------------------------------------------------------------------------------

SOP 001: HANDLING LICENSE GENERATION AND PROVISIONING
   - Trigger: New successful Stripe checkout event.
   - Action:
     1. Automatically generate the key using the secure key generation method.
     2. For Enterprise, the price is fetched dynamically from the `nexus_plan_enterprise_price` setting.
     3. Update the master registry option `nexus_ai_issued_licenses` with the new key,
        setting plan, activation status, and expiry parameters.
     4. Email the client their license key along with activation instructions. For Enterprise plans, dispatch dedicated SLA and setup checklists.

SOP 002: DEBATING AND RESOLVING SUBSCRIPTION CANCELLATIONS
   - Trigger: User clicks "Cancel Plan" inside the billing panel.
   - Action:
     1. Submit POST request to `/billing/cancel` to flag cancellation pending status.
     2. On expiration date, remove the cryptographic signature from local client database,
        automatically downgrading the workspace capacity back to Starter tier without breaking site files.

SOP 003: AUDITING CLIENT LICENSING ANOMALIES
   - Trigger: Flagged mismatches in license validation or manual database tampering.
   - Action:
     1. Run `\NexusAI\Workforce\API\BillingController::verify_active_license()`.
     2. If verification returns false, immediately restrict active workspace agents and
        log an event "license_compromised_alert" in the system audit trail.

--------------------------------------------------------------------------------
PART 5: END-TO-END TUTORIAL: SETTING UP RECURRING PAYMENTS AND LICENSE LOCKS
--------------------------------------------------------------------------------

STEP 1: INSTALL BOTH PLUGINS
   Install both `wp-ai-workforce` (the core Multi-Agent OS) and `wp-ai-licensing`
   (the SaaS payment and key licensing server bridge) on your WordPress instance.

STEP 2: ACCESS THE CONTROLLER
   Navigate to Nexus AI > License & Payments in your WordPress Admin sidebar. Here you
   can see the live billing dashboards, key management console, and Stripe settings.

STEP 3: INTEGRATE STRIPE
   Input your Stripe Publishable Key, Secret Key, and Webhook Secret in the Stripe
   Gateway card, then select "Sandbox" billing mode for safe payment testing.

STEP 4: ISSUE A LICENSE
   In the Key Issuance Dashboard card:
   1. Select "Agency Plan" from the plan tier dropdown.
   2. Click "Generate License Key".
   3. Copy the newly generated key, e.g., `NEXUS-AGENCY-ABCD-EFGH`.

STEP 5: ACTIVATE THE LICENSE
   Go to the Client Activation Console card:
   1. Paste the generated key into the license key field.
   2. Click "Activate Local License".
   3. Observe the success notice showing that your workspace has been successfully
      upgraded to the cryptographically-signed AGENCY plan, unlocking 100 concurrent AI agents!
